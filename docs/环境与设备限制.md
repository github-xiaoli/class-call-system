# 环境与设备限制说明：改程序解决不了的问题

> 适用版本：**2.0.30 及以后**（本版新增 `/cert`、`/plain`、`/logs`、`/api/health` 四个排障入口）
> 本文档只写**软件改不了、只能靠现场设置或换方式**的问题。所有能在代码里解决的，都已经在软件里解决了，不在此列。

## 0. 先看这一张表

| 你看到的症状 | 真正的原因 | 只能这样解决 |
|---|---|---|
| 手机输 `http://名字.local:8000` → "找不到服务器" | 这台设备/系统**不解析** `.local`（mDNS） | 改用 `http://电脑IP:8000` |
| iPhone/iPad 打开就**白屏、没有任何报错** | 自签证书 + 第三方浏览器没有"继续访问"按钮 | 用 Safari，或装证书并开启「完全信任」 |
| Safari 能开、Chrome/Edge 白屏 | 同上（不是权限问题） | 同上 |
| 手机浏览器 → "您的连接不是私密连接" | 自签证书不被信任 | 点「继续/高级」或装证书 |
| 昨天能开、今天打不开（IP 没变） | 校园 AP 关了多播 / 开了客户端隔离 | 用 IP；或换网络；或手机热点 |
| 二维码突然失效 | 电脑 IP 变了（DHCP 租约） | 路由器做 DHCP 保留；或重新生成二维码 |
| 手机连得上电脑，但电脑上看不到手机请求 | Windows 防火墙"公用网络"拦入站 | 首次运行点"允许访问"；或放行端口 |
| 教室电脑名字能解析、家里不行 | 网络环境差异（多播/隔离） | 用 IP，不依赖名字 |
| 在线更新一直失败 | 学校网络屏蔽 GitHub | 用安装包手动更新 |

## 1. 手机 / 平板端

### 1.1 `名字.local` 打不开（mDNS 名字解析不了）

**现象**：手机浏览器输入 `http://nine6.local:8000`，提示"找不到服务器 / 无法访问此网站"；换成 `http://192.168.x.x:8000` 立刻就能打开。

**原因**：`.local` 这种名字要靠**设备自己**用 mDNS 解析。能不能解析，取决于**操作系统/ROM，跟浏览器无关**——同一个 Edge，在不同设备上表现就不同：

| 设备（实测） | 系统 | 能否解析 `.local` |
|---|---|---|
| 荣耀 30S | 鸿蒙 3.0（AOSP 10 底子） | ❌ 不能 |
| Lenovo TB310FU | LineageOS 23 GSI（Android 16） | ✅ 能 |
| iPhone / iPad / Mac | iOS / iPadOS / macOS | ✅ 能 |
| Windows 10/11 电脑 | 自带 mDNS | ✅ 能 |

所以"换浏览器能解决"是错觉：Chrome、Edge、夸克在安卓上都走同一个系统解析器。

**现场处理**：
1. 手机一律用 `http://电脑IP:端口`
2. 想确认这台设备到底支不支持名字：让它打开 `http://电脑IP:8000/plain` 与 `http://名字.local:8000/plain`，看能不能出同一页

**软件已做的规避**：二维码、配对地址、向导里的手机地址**默认都用 IP**，`.local` 只作为文字备选。

---

### 1.2 iPhone / iPad **白屏、没有任何错误提示**

**现象**：Safari 或 Chrome/Edge 打开后一片白，不报错，也不转圈。

**原因（两条叠加）**：
1. 软件用的是**自签名证书**，苹果默认不信任；
2. **Safari 遇到证书问题会弹"显示详细信息 → 访问此网站"，而 iPhone 上的 Chrome / Edge / 夸克没有这个界面**——它们底层都是 WebKit，但跳不过去，于是请求直接失败 → 白屏。

另外，Apple 的规定是：**手动安装的证书不会自动受信任**，必须在「证书信任设置」里手动打开「完全信任」。

**现场处理（一次搞定）**：
1. iPhone 用 **Safari** 打开 `https://电脑IP:安全端口/cert`
2. 点「下载描述文件」→ 允许
3. 设置 → 已下载描述文件（或：通用 → VPN 与设备管理）→ **安装** → 输锁屏密码
4. **设置 → 通用 → 关于本机 → 证书信任设置 → 打开「班级叫号器本机根证书」的完全信任**

做完后，Safari、Chrome、Edge 都不会再白屏，也不用每次点"继续"。

**软件已做的规避**：软件会自动生成一份**本机根证书**（10 年有效）并据此签发服务器证书（证书里同时写了 DNS 名字和局域网 IP），提供 `/cert`（手机引导页）、`/cert.mobileconfig`（苹果描述文件）、`/cert.crt`（安卓/电脑用）；主页还加了**白屏兜底提示**（脚本没跑起来时 4 秒后弹出可点击的下一步）。

> ⚠️ 这三个入口是 **2.0.30 新增**的。如果你装的还是 2.0.29 或更早，打开 `/cert` 会是 404——请先更新到 2.0.30 及以上。

---

### 1.3 装了证书还是白屏

按顺序检查：
1. 有没有做「**证书信任设置 → 完全信任**」这一步（最常见）
2. 装的是不是**旧版**软件签的证书（旧版没有根证书，装了也没用）→ 换 2.0.30 以后版本，重新装一次
3. 装完有没有**完全关掉浏览器重开**（后台标签页不算）
4. 换 Safari 试一次，确认是不是那个浏览器的缓存/内容拦截器（如 AdGuard）

---

### 1.4 「设置 → 隐私与安全性 → 本地网络」里**找不到 Safari**

**这是正常的**。那个开关管的是**第三方 App 以 App 身份访问局域网**（iOS 14 起的本地网络隐私）。Safari 是系统浏览器，不走这套权限模型，所以永远不会出现在列表里。

列表里只会出现：① 你装的第三方 App；② **它已经尝试过一次**局域网访问（弹过"想查找并连接本地网络上的设备"之后）。
—— 如果列表里没有 Chrome/Edge：先让它打开一次 `http://电脑IP:8000`，弹窗选允许，再回来看。

---

### 1.5 会干扰局域网访问的三个手机开关

| 开关 | 路径 | 建议 |
|---|---|---|
| iCloud **私密中继** | 设置 → 顶部 Apple ID → iCloud → 私密中继 | 关闭 |
| **限制 IP 地址跟踪** | 设置 → 无线局域网 → 当前 Wi-Fi 右侧 ⓘ | 关闭 |
| **私有无线局域网地址** | 同上 | 关闭（关掉后 Wi-Fi 会重连一次） |

---

### 1.6 安卓 / 鸿蒙提示"您的连接不是私密连接"

自签证书在安卓上的正常提示，点「**高级 → 继续前往**」即可；或按 `/cert` 页里的安卓步骤装一次 CA 证书（设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书）。

---

### 1.7 清除浏览器数据 = 激活失效（无法恢复）

激活用的是**浏览器里生成的一对密钥**（私钥不出浏览器）。清缓存、卸载浏览器、恢复出厂、刷机、用无痕模式，都会让私钥丢失，只能**在电脑上重新生成密码再激活一次**。

告诉使用者：**不要清这个浏览器的数据**。

---

### 1.8 iOS 对证书有效期的硬限制：825 天

iOS / 新版 macOS 会**直接拒绝**有效期超过 825 天的服务器证书。旧版本软件签过 10 年的证书，在 iPhone 上的表现就是"打不开 / 服务器已停止响应"。2.0.24 起已改为 365 天证书，2.0.30 起改为"根证书 10 年 + 服务器证书 365 天"。**从很旧的版本升级上来的电脑，第一次启动会自动重签一次证书，手机端需要重新装一次证书。**

---

### 1.9 iPhone 上换浏览器解决不了的问题

App Store 规则规定：**所有 iOS 浏览器都必须用 WebKit 内核**（只有欧盟、日本在法规上允许替代内核，普通用户拿不到）。所以：

- 换浏览器**不会**改变页面渲染/ATS/证书行为
- 换浏览器**只会**改变外壳自己的声明（有的允许明文 http，有的不允许）与是否有"继续访问"界面

真正有效的选择只有两个：**用 Safari**，或**装证书**。

## 2. 网络 / 路由器 / 校园网

### 2.1 校园 AP 关闭多播 → mDNS 名字"时好时坏"

很多学校 AP 出于省电/安全默认**过滤多播（UDP 5353）**，或对无线客户端做**组播转单播**处理。表现就是：同一个名字，有时能解析、有时不能，重启手机又好一会儿。

**这类网络里 `.local` 永远不可靠**，请直接用 IP。IP 访问只走普通 TCP，和多播无关。

### 2.2 客户端隔离 / 无线隔离（AP Isolation）

学校为防互访，会让同一个 Wi-Fi 下的设备**互相看不到**。现象：手机能上网，但连不上教室里任何一台电脑（IP 也不行）。

**处理**：换到不做隔离的网络（教师办公室网、自建路由器、手机热点）。

### 2.3 不同网段 / VLAN

教室电脑在 10.x，学生手机在 192.168.x（或反过来）→ 即使没有隔离也访问不了。**IP 和名字都不行**，只能让两者在同一网段。

### 2.4 电脑 IP 会变（DHCP 租约）→ 二维码失效

二维码里放的是 IP，IP 一变旧二维码就作废。三种做法：

| 做法 | 会不会撞 IP | 说明 |
|---|---|---|
| **路由器里做 DHCP 保留（MAC 绑定）** | 不会 | **最推荐**。电脑仍用"自动获取"，路由器每次发同一个 IP，换网络也不影响 |
| 静态 IP，且**选在 DHCP 池外** | 不会 | 例如池 100–199，就用 .50 或 .240；必须同时填对掩码/网关/DNS |
| 什么都不改 | 不会 | 每次用面板上显示的当前 IP，或当场重新生成二维码 |

⚠️ **静态 IP 千万不要填在 DHCP 池里**：路由器不知道你手动占了它，会把同一地址发给别人 → 双方轮流掉线（Windows 会提示"IP 地址冲突"并跳到 169.254）。另外 Windows 的静态 IP 是绑在**网卡**上的，不是绑 Wi-Fi 名——白天连学校网、晚上连手机热点的电脑，设静态后会有一边不通。

### 2.5 学校网络屏蔽 GitHub → 在线更新失败

软件内置了 raw.githubusercontent / jsDelivr / gh-proxy / ghfast 四个镜像轮询，但**全部被墙**时就无法在线更新。此时用**安装包手动更新**（覆盖安装，名单和数据不丢）。

### 2.6 系统时间不准

时间偏差过大可能导致证书校验失败、更新校验失败。把电脑和手机都设为自动对时。

### 2.7 访客网络 / 上网认证门户

需要网页登录的校园网（Portal），未认证时所有内网互访也可能被重定向。先完成认证再连。

## 3. Windows 电脑端

### 3.1 防火墙"公用网络"拦入站

Windows 默认对**公用网络**丢弃入站连接。软件第一次运行时系统会弹"是否允许访问"，**必须允许**（勾上专用+公用）。

坑在于：**规则是按当时的网络类型记的**。电脑第一次在"专用网络"下允许了，之后连上一个被判为"公用"的网络（学校 Wi-Fi 常被判公用），规则就不生效 → 手机又连不上。处理：在设置里重新允许，或用 `netsh advfirewall` 放行端口（需管理员）。

### 3.2 多网卡 / 虚拟网卡

电脑常同时有：有线、无线、Hyper-V 的 `vEthernet`、WSL、VMware/VirtualBox、VPN、Wi-Fi Direct（`本地连接* 2`）。**这些虚拟网卡的 IP 手机永远连不上**。
2.0.30 起软件用原生 API（`GetAdaptersAddresses`）判断"有没有默认网关 / 是否虚拟"，默认只广播真实网卡；设置页的「mDNS 诊断」会列出每块网卡被跳过及原因。**但如果教室电脑有"有线 + 无线"两块真实网卡，需要确认手机连的是哪张网**（诊断里会显示广播的是哪个 IP）。

### 3.3 组策略禁用 PowerShell / WMI

旧版（≤2.0.29）用 PowerShell 枚举网卡，被组策略禁用时会退化成"所有 IP 一起广播"→ 手机拿到连不上的地址。**2.0.30 起改用系统原生 API，不再依赖 PowerShell。**
但同环境的其它限制（下面 3.5）仍可能生效。

### 3.4 没有管理员权限 / 学校禁止安装

用**便携版**（zip 解压即用，不需要安装、不写注册表），或安装包的**测试模式**（装到当前用户目录，不提权）。

### 3.5 AppLocker / 软件限制策略拦截 `python.exe`

软件自带便携 Python。若学校策略只允许白名单程序运行，自带解释器可能被拦。处理：请管理员放行安装目录，或换一台不受限制的电脑。

### 3.6 端口落在 Windows 保留段

Hyper-V / WSL / WinNAT 会占掉一些端口段，绑定会报 `WinError 10013`。软件会自动跳过并换端口（安全端口默认 9443 就是为了避开常见的 8443），设置页保存端口前也会先校验。

### 3.7 以管理员启动后，Edge 弹「现有实例正在以提升的权限运行」

**与软件无关**：软件以管理员身份启动后自动打开的 Edge 继承了管理员权限；之后你用普通权限再开 Edge，就会弹"是否用普通权限重启现有实例"。
处理：点是（Y），或把那个管理员权限的 Edge 全部关掉。

### 3.8 摄像头 / 麦克风被占用或禁止

监控、对讲、远控需要摄像头/麦克风。被其它程序（钉钉、腾讯会议、希沃）占用，或被系统隐私设置禁止、被杀软拦截时，功能会不可用。软件里"监控对讲"页能看到设备列表和失败原因。

### 3.9 睡眠 / 唤醒、切换网络后临时失效

2.0.30 起有网卡监听线程：换网、插网线、Wi-Fi 后连上、IP 变化都会自动重新注册 mDNS。但**电脑睡眠期间一切服务都会停**，唤醒后需要几秒恢复；教室电脑建议在电源设置里关掉睡眠。

## 4. 为什么这些"不能靠改程序解决"

| 限制 | 归属 | 软件的对策 |
|---|---|---|
| `.local` 能否解析 | 设备/系统的域名解析器 | 二维码改用 IP，名字只做备选 |
| iOS 第三方浏览器跳过不信任证书 | App Store 规则 + WKWebView 无该界面 | 提供根证书 + 描述文件，装一次永久信任 |
| 苹果要求手动信任证书 | Apple 安全策略 | `/cert` 引导页写清 4 步 |
| AP 过滤多播 / 客户端隔离 | 网络设备厂商策略 | 用 IP；`.local` 不再作为唯一入口 |
| DHCP 改 IP | 网络管理员策略 | 建议 DHCP 保留；二维码随时可重新生成 |
| GitHub 不可达 | 出口网络策略 | 四个镜像 + 安装包手动更新 |
| 防火墙按网络类型生效 | Windows 安全模型 | 启动自检会报"手机连不上"的常见原因 |
| 虚拟网卡被广播 | 系统网卡枚举 | 原生 API 判断 + 只广播真实网卡 + 诊断面板 |
| 无管理员权限 | 单位 IT 策略 | 便携版 / 测试模式安装 |

## 5. 现场应急手段（都不用改程序）

1. **用 IP**：手机打开 `http://电脑IP:8000`（叫号全部功能）；`https://电脑IP:9443`（激活/监控/远控）。
2. **先开 `/plain`**：不含脚本的极简页。能打开 ⇒ 网络和服务正常，白屏是浏览器/证书问题。
3. **再看 `/api/health`**：返回 JSON，能看出你连到的是哪台电脑、走的 http 还是 https、以及你的 IP/UA。
4. **电脑上看 `/logs`**：实时运行日志，可一键导出 txt（稳定版主页不显示入口，直接输网址可进）。
5. **设置里点「mDNS 诊断」**：列出每块网卡、为什么被跳过、当前广播了哪些地址。
6. **临时换网络**：手机开热点给电脑连（电脑做客户端时），或自带一个小路由器——这种"自己掌控"的网络通常不做多播过滤与客户端隔离。
7. **固定 IP**：在路由器里给教室电脑做 DHCP 保留（不是手动填静态 IP），二维码可长期有效。
